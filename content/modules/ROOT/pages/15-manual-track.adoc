= Build & Deploy an MCP Server
:navtitle: Build & Deploy an MCP Server

Step-by-step guide to build, deploy, and use an MCP server on OpenShift using `oc` commands and `curl`.

The server code is pre-built and ready in `server/`. You read it, build it, deploy it, and use it.

*Duration:* ~45 minutes

TIP: This is the primary workshop track. If you prefer an AI agent to generate the code and walk you through each step interactively, see the optional xref:03-stage1-welcome.adoc[agent-guided track] (Stages 1–9).

== Before you start

You need:

* A terminal in your DevSpaces workspace — open one with *F1 → type `terminal select` → pick `dev-tools`*
* The pre-built server code in `server/` (cloned with the workshop repo)

== Step 0: Read the code

Open and read `server/server.py`. It has section comments explaining every concept:

[source,bash]
----
cat server/server.py | head -50
----

Key things to notice:

* `MCPServer("stock-market")` — creates the server instance
* `@server.tool(name=..., description=...)` — each decorated function becomes an MCP tool
* Type hints on parameters → JSON Schema for the LLM
* Docstrings → tool descriptions the LLM reads
* `server.run(transport="streamable-http", host="0.0.0.0", port=8080)` → HTTP listener

The server has 9 tools that fetch live data from Yahoo Finance. No API key needed.

== Step 1: Set your variables

[source,bash]
----
# Your username prefix (ask your facilitator — usually user1, user2, etc.)
export USER_PREFIX=user1

# Your namespace (auto-detected from current project)
export USER_NAMESPACE=$(oc project -q)

echo "Prefix:    $USER_PREFIX"
echo "Namespace: $USER_NAMESPACE"
----

Expected output:
----
Prefix:    user1
Namespace: user1-devspaces
----

== Step 2: Build the container image

An OpenShift *BuildConfig* compiles your code into a container image inside the cluster — no local Docker or Podman needed.

[source,bash]
----
# Create the BuildConfig (one-time setup)
oc new-build --name=${USER_PREFIX}-stock-mcp \
  --strategy=docker \
  --binary \
  --to=${USER_PREFIX}-stock-mcp:latest

# Start the build from the server/ directory
oc start-build ${USER_PREFIX}-stock-mcp \
  --from-dir=server/ \
  --follow
----

The `--follow` flag streams build logs. You should see pip installing `mcp[cli]` and `yfinance`, then a "Push successful" message.

If the build fails, check:
[source,bash]
----
oc logs bc/${USER_PREFIX}-stock-mcp
----

== Step 3: Get the image digest

The MCPServer CR needs the *exact* image reference (with sha256 digest), not a mutable `:latest` tag.

[source,bash]
----
export IMAGE_REF=$(oc get istag ${USER_PREFIX}-stock-mcp:latest \
  -o jsonpath='{.image.dockerImageReference}')

echo "Image: $IMAGE_REF"
----

Expected output (your digest will differ):
----
Image: image-registry.openshift-image-registry.svc:5000/user1-devspaces/user1-stock-mcp@sha256:abc123...
----

== Step 4: Deploy the MCPServer CR

This is the key step. Instead of manually creating Deployments and Services, you create a single `MCPServer` custom resource. The *MCP Lifecycle Operator* then:

* Creates a security-hardened *Deployment* (non-root, drop ALL capabilities, read-only filesystem)
* Creates a *Service* (ClusterIP on port 8080)
* Creates a *NetworkPolicy* for network segmentation
* Performs an *MCP protocol handshake* — it sends an `initialize` JSON-RPC call to verify your server responds correctly

[source,bash]
----
sed "s|USER_PREFIX|$USER_PREFIX|g; s|IMAGE_REF|$IMAGE_REF|g" \
  deploy/01-mcpserver.yaml | oc apply -f -
----

Wait for it to become Ready:

[source,bash]
----
# Watch until READY shows True (Ctrl+C to stop watching)
oc get mcpserver ${USER_PREFIX}-stock-mcp -w
----

Expected output:
----
NAME               READY   AGE
user1-stock-mcp    True    45s
----

If it stays not-ready for more than 2 minutes:
[source,bash]
----
# Check events and conditions
oc describe mcpserver ${USER_PREFIX}-stock-mcp

# Check the server pod logs
oc logs deployment/${USER_PREFIX}-stock-mcp
----

Common issues:

[cols="1,2",options="header"]
|===
| Symptom | Fix

| `HandshakeFailed`
| Server isn't responding on port 8080 at `/mcp`. Check that `server.py` uses `host="0.0.0.0"` and `port=8080`.

| `DeploymentUnavailable`
| Pod is crashing. Check `oc logs deployment/${USER_PREFIX}-stock-mcp` for Python import errors.

| `ImagePullBackOff`
| Image reference is wrong. Re-run Step 3 to get the correct digest.
|===

== Step 5: Verify in AI Hub

Open the *OpenShift AI dashboard* in your browser:

. Navigate to *AI Hub → MCP servers → Deployments*
. Your `${USER_PREFIX}-stock-mcp` should appear with a *Ready* badge
. Click it to see the 9 tools the operator discovered during the handshake

This confirms Layer 1 (Deploy) and Layer 2 (Discover) of the MCP Lifecycle are working.

== Step 6: Get the MCP Gateway hostname

The MCP Gateway provides a single, governed entry point for all MCP servers. You need its external hostname:

[source,bash]
----
export GATEWAY_HOSTNAME=$(oc get gateway mcp-gateway -n mcp-system \
  -o jsonpath='{.spec.listeners[0].hostname}')

echo "Gateway: $GATEWAY_HOSTNAME"
----

Expected output:
----
Gateway: mcp-gateway.apps.ocp.example.com
----

== Step 7: Create the HTTPRoute

The HTTPRoute tells the gateway: "route traffic at `/mcp/${USER_PREFIX}-stock` to my MCPServer's Service."

[source,bash]
----
sed "s|USER_PREFIX|$USER_PREFIX|g; s|GATEWAY_HOSTNAME|$GATEWAY_HOSTNAME|g" \
  deploy/02-httproute.yaml | oc apply -f -
----

Verify:
[source,bash]
----
oc describe httproute ${USER_PREFIX}-stock-mcp | grep -A2 "Conditions:"
----

Expected: you should see `Accepted: True` in the conditions. If not, check that the gateway hostname matches and the MCP Gateway is programmed (`oc get gateway mcp-gateway -n mcp-system`).

== Step 8: Register with the MCP Gateway

The *MCPServerRegistration* tells the gateway about your tools and adds a *prefix* to avoid name collisions. With 30 participants, each having a `get_stock_info` tool, the prefix ensures they don't clash (e.g., `user1_stock_get_stock_info`).

[source,bash]
----
sed "s|USER_PREFIX|$USER_PREFIX|g" \
  deploy/03-mcpserverregistration.yaml | oc apply -f -
----

IMPORTANT: The field is `prefix`, NOT `toolPrefix`. Using `toolPrefix` is silently ignored — your tools won't be prefixed and may collide.

The `targetRef` points to your HTTPRoute — the gateway discovers your backend service from the route.

Verify:
[source,bash]
----
oc get mcpserverregistration ${USER_PREFIX}-stock-mcp
----

== Step 9: Test your MCP server with curl

Now the payoff — you'll talk the *MCP protocol* directly to your server. MCP uses JSON-RPC 2.0 over HTTP, so three `curl` commands prove the entire stack works.

First, set the MCP endpoint URL. Your MCPServer's Service is accessible within the cluster:

[source,bash]
----
export MCP_URL="http://${USER_PREFIX}-stock-mcp:8080/mcp"
echo "MCP endpoint: $MCP_URL"
----

=== 9a. Initialize (MCP handshake)

Every MCP session starts with an `initialize` call. The client and server exchange capabilities and agree on a protocol version.

[source,bash]
----
curl -s -D /tmp/mcp-headers.txt -X POST "$MCP_URL" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2025-03-26",
      "capabilities": {},
      "clientInfo": {"name": "manual-test", "version": "1.0"}
    }
  }'
----

Expected: a JSON response with `"result"` containing server info and capabilities. The server also returns an `Mcp-Session-Id` header that you need for subsequent calls.

Save the session ID:
[source,bash]
----
export MCP_SESSION=$(grep -i mcp-session-id /tmp/mcp-headers.txt | tr -d '\r' | awk '{print $2}')
echo "Session: $MCP_SESSION"
----

=== 9b. List tools (tool discovery)

This is what an AI agent calls to find out what your server can do. The response is the same tool list you saw in the AI Hub.

[source,bash]
----
curl -s -X POST "$MCP_URL" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Mcp-Session-Id: $MCP_SESSION" \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/list",
    "params": {}
  }'
----

Expected: a `"result"` object with a `"tools"` array listing all 9 tools. Each tool has a `name`, `description`, and `inputSchema` — the same metadata you defined with decorators and docstrings in `server.py`.

=== 9c. Call a tool (live data)

Now call a tool and get real stock data. This is exactly what an LLM does when it decides to use a tool.

[source,bash]
----
curl -s -X POST "$MCP_URL" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Mcp-Session-Id: $MCP_SESSION" \
  -d '{
    "jsonrpc": "2.0",
    "id": 3,
    "method": "tools/call",
    "params": {
      "name": "get_stock_info",
      "arguments": {"ticker": "AAPL"}
    }
  }'
----

Expected: live Apple stock data — current price, volume, market cap, 52-week range. This data came from Yahoo Finance, processed by YOUR server, deployed on OpenShift.

Try more tools:

[source,bash]
----
# Get latest news for Tesla
curl -s -X POST "$MCP_URL" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Mcp-Session-Id: $MCP_SESSION" \
  -d '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"get_stock_news","arguments":{"ticker":"TSLA"}}}'

# Get analyst recommendations for NVIDIA
curl -s -X POST "$MCP_URL" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Mcp-Session-Id: $MCP_SESSION" \
  -d '{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"get_recommendations","arguments":{"ticker":"NVDA"}}}'
----

=== What just happened

You spoke the MCP protocol directly:

. *Initialize* — handshake, establish session
. *tools/list* — discover available tools (this is what AI agents call to learn your capabilities)
. *tools/call* — invoke a tool with arguments and get results (this is what happens when an LLM decides to use a tool)

The same three calls happen behind the scenes when any MCP client (OpenCode, Claude, Cursor, etc.) connects to your server. You just did it by hand.

=== Troubleshooting

[cols="1,2",options="header"]
|===
| Symptom | Fix

| `Connection refused` or timeout
| The MCP Gateway may not be reachable. Verify: `oc get gateway mcp-gateway -n mcp-system` shows `PROGRAMMED=True`.

| `404 Not Found`
| The HTTPRoute path does not match. Check: `oc describe httproute ${USER_PREFIX}-stock-mcp`. The path should be `/mcp/${USER_PREFIX}-stock`.

| `initialize` returns an error
| Your MCPServer pod may not be running. Check: `oc get mcpserver ${USER_PREFIX}-stock-mcp` shows `READY=True`. Check logs: `oc logs deployment/${USER_PREFIX}-stock-mcp`.

| `tools/list` returns empty
| The MCPServerRegistration may not be ready. Check: `oc get mcpserverregistration ${USER_PREFIX}-stock-mcp`.

| `tools/call` returns an error
| Check your MCPServer pod logs: `oc logs deployment/${USER_PREFIX}-stock-mcp`. Yahoo Finance may have rate-limited the request — wait a moment and try again.
|===

== Cleanup

Remove resources in reverse dependency order:

[source,bash]
----
# 1. Gateway registration
oc delete mcpserverregistration ${USER_PREFIX}-stock-mcp

# 2. Gateway route
oc delete httproute ${USER_PREFIX}-stock-mcp

# 3. MCPServer CR (operator auto-deletes Deployment, Service, NetworkPolicy)
oc delete mcpserver ${USER_PREFIX}-stock-mcp

# 4. Build artifacts
oc delete bc/${USER_PREFIX}-stock-mcp
oc delete is/${USER_PREFIX}-stock-mcp
----

Verify everything is gone:
[source,bash]
----
oc get mcpserver,mcpserverregistration,httproute,bc,is 2>/dev/null | grep stock-mcp
----

Expected: no output.

== What you just did

You completed the full *MCP Lifecycle* on OpenShift:

[cols="1,2,2",options="header"]
|===
| Layer | What | Resource

| *Build*
| OpenShift binary build compiled your code into a container image
| BuildConfig + ImageStream

| *Deploy*
| MCP Lifecycle Operator created and hardened your server
| MCPServer CR → Deployment + Service + NetworkPolicy

| *Discover*
| AI Hub made your server browsable
| AI Hub → MCP servers → Deployments

| *Route & Govern*
| MCP Gateway provides federated access with tool prefixing
| HTTPRoute + MCPServerRegistration

| *Test*
| You spoke the MCP protocol directly via curl
| `initialize` → `tools/list` → `tools/call`
|===

All from 3 YAML files, 3 curl commands, and a handful of `oc` commands. Any MCP client — OpenCode, Claude, Cursor, or your own code — can connect to the MCP Gateway at `https://${GATEWAY_HOSTNAME}/mcp` and discover your tools alongside every other participant's servers. The gateway federates all registered tools under one endpoint, with your prefix (`${USER_PREFIX}_stock`) preventing name collisions.
