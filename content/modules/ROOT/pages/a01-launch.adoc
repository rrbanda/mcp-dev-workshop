= Launch Your Workspace
:navtitle: Launch Your Workspace

Your workspace is running and you have verified the LLM in the Prerequisites
page. Now get oriented -- learn where things are in the IDE, explore the
project layout, and verify the OpenCode agent responds.

== Learning objectives

* Navigate the VS Code editor (file tree, terminal, ports).
* Locate the workshop project files and understand the directory structure.
* Open the OpenCode Web UI and send a message to the agent.
* Confirm environment variables are set.

== Your IDE at a glance

You are working in *VS Code in the browser*, provided by Red Hat OpenShift
DevSpaces. Here is what you should see:

[cols="1,3",options="header"]
|===
| Area | What is there

| *Left sidebar -- file tree*
| The `/projects/mcp-dev-workshop` directory. Click any file to open it in
  the editor. You will spend most of your time in the `scaffold/` directory.

| *Bottom panel -- terminal*
| One or more terminal tabs. `oc`, `python`, `pip`, `curl`, `make` are all
  available. You are already logged in.

| *Top menu bar*
| File, Edit, Terminal, Help. Use *Terminal -> New Terminal* if you need
  another terminal tab.

| *Ports / Endpoints tab*
| Shows exposed ports. Port 4096 is the OpenCode Web UI -- you will use this
  for every exercise.
|===

== Exercise 1: Open the OpenCode Web UI

In the VS Code editor, look at the bottom panel or the *Ports* tab.
Find the endpoint labeled *opencode-web* on port *4096*.
Click the link (or the globe icon) to open it in a new browser tab.
Enter the *OpenCode Web Password* from your credentials card.

You should see the OpenCode chat interface with a prompt input at the bottom.

Type a simple message to verify the agent is connected:

----
What directory am I in, and what files do you see?
----

Expected result: The agent responds describing the `/projects/mcp-dev-workshop`
directory and lists files like `scaffold/`, `Makefile`, `.opencode/skills/`, etc.

[IMPORTANT]
====
If the agent returns a connection error or timeout, open a terminal and verify:

[source,bash,role="execute"]
----
echo $OPENAI_BASE_URL
----

This should print the MaaS gateway URL. If empty, contact the facilitator.
====

== Exercise 2: Explore the project

In the file tree (left sidebar), expand `mcp-dev-workshop`. Or use the terminal:

[source,bash,role="execute"]
----
cd /projects/mcp-dev-workshop && find . -maxdepth 2 -type f | grep -v '.git/' | sort | head -25
----

Key directories and files:

[cols="1,3",options="header"]
|===
| Path | Purpose

| `scaffold/`
| Where you build your MCP server. Contains starter files (`requirements.txt`,
  `Containerfile`, `deployment.yaml`). You will create `server.py` here in
  Module 3.

| `solutions/`
| Reference solutions for each module. Use these if you fall behind.

| `.opencode/skills/`
| Agent Skills (SKILL.md files) that teach the agent MCP patterns, yfinance
  API, and the server specification. The agent loads these on demand.

| `Makefile`
| Workshop commands: `make validate`, `make build-image`, `make deploy`,
  `make test-mcp`, `make clean`.
|===

== Exercise 3: Ask the agent to discover skills

In the OpenCode chat:

----
What skills do you have available? List them.
----

Expected result: The agent lists skills including `build-mcp-server`,
`yfinance-api`, and `stock-market-mcp-spec` -- with one-line descriptions.
It shows each skill name but does *not* load the full content yet (lazy loading).

Now ask it to load one:

----
Load the build-mcp-server skill and summarize what it teaches you.
----

Expected result: The agent reads the full SKILL.md and summarizes the MCP
Python SDK v2 patterns it learned.

== Exercise 4: Confirm environment variables

[source,bash,role="execute"]
----
echo "User:      $(oc whoami)"
echo "Namespace: $(oc project -q)"
echo "API URL:   $OPENAI_BASE_URL"
echo "Model:     $VLLM_MODEL_ID"
echo "API Key:   ${OPENAI_API_KEY:+set (hidden)}"
----

Expected result: Five lines. Username, namespace (`<username>-devspaces`),
the MaaS gateway URL, the model ID, and `set (hidden)` for the API key.
All five must be non-empty.

[IMPORTANT]
====
If any value is empty or shows an error, *stop and ask the facilitator*.
The remaining modules depend on all four being set.
====
