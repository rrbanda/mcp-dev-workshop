= Build with the Agent
:navtitle: Build with the Agent

This is the core module. You tell the AI agent what tools you want, the agent
loads three skills and generates a complete MCP server that provides real-time
stock market data. You review the code and optionally customize it.

== Learning objectives

* Use the agent and its loaded skills to generate a stock market MCP server.
* Identify the MCP Python SDK v2 patterns in the generated code.
* Understand how type hints and Enum classes map to JSON Schema.
* Add or modify a tool via natural-language instruction.

== Exercise 1: Ask the agent to build your MCP server

In the OpenCode chat, give the agent a clear description of what you want.
Here is a suggested prompt -- feel free to customize it:

----
Build me a stock market MCP server with these tools:

1. get_historical_stock_prices - Get historical OHLCV data for a ticker
2. get_stock_info - Get comprehensive stock information (price, metrics, company details)
3. get_stock_news - Get latest news articles for a stock
4. get_stock_actions - Get dividends and stock splits history
5. get_financial_statement - Get income statement, balance sheet, or cash flow
6. get_holder_info - Get holder data (institutional, mutual fund, insider)
7. get_option_expiration_dates - Get available options expiration dates
8. get_option_chain - Get options chain with strike window and field projection
9. get_recommendations - Get analyst recommendations or upgrades/downgrades

Use yfinance for data (no API key needed). Put the server in scaffold/server.py.
Also create scaffold/requirements.txt, scaffold/Containerfile, and
scaffold/deployment.yaml.

Include proper Enum types for financial_type, holder_type, and
recommendation_type parameters. Add a normalize_ticker helper for US class
shares (BRK.B to BRK-B). Support both stdio (local dev) and streamable-http
(deployment) transports based on an MCP_TRANSPORT environment variable.
----

Expected result: The agent loads the `build-mcp-server`, `yfinance-api`, and
`stock-market-mcp-spec` skills and generates four files:

* `scaffold/server.py` -- the MCP server with all nine tools
* `scaffold/requirements.txt` -- with `mcp[cli]>=2.1.0` and `yfinance>=1.6.0`
* `scaffold/Containerfile` -- UBI9 Python image, pip install, CMD
* `scaffold/deployment.yaml` -- Deployment + Service for OpenShift

Watch the agent's output -- you should see it reference the skills and
produce structured Python code.

[IMPORTANT]
====
If the agent produces code that uses `FastMCP` instead of `MCPServer`, ask it
to update the import. `FastMCP` was the v1 name -- it is *removed* in SDK v2.
The correct v2 import is `from mcp.server import MCPServer`.
====

== Exercise 2: Review the generated code

Open `scaffold/server.py` in the IDE or terminal:

[source,bash,role="execute"]
----
cat scaffold/server.py
----

Check for these SDK v2 patterns:

[cols="1,2",options="header"]
|===
| Pattern | What to look for

| *Import*
| `from mcp.server import MCPServer` and `import yfinance as yf`

| *Server instance*
| `server = MCPServer("stock-market", instructions="...")`

| *Enum types*
| `FinancialType`, `HolderType`, `RecommendationType` as `str, Enum` subclasses

| *Ticker normalization*
| `normalize_ticker()` function converting `BRK.B` to `BRK-B`

| *Tool decorator*
| `@server.tool(name="...", description="...")` above each function

| *Async tools*
| `async def get_stock_info(ticker: str) -> str:`

| *Type hints*
| Enum types in parameters, `float` or `None`, `list[str]` or `None`

| *Error handling*
| `try/except Exception` wrapping all tool bodies

| *Transport switch*
| `MCP_TRANSPORT` env var selects stdio or streamable-http

| *Entry point*
| `if __name__ == "__main__": main()`
|===

== Exercise 3: Review the deployment artifacts

Check the Containerfile:

[source,bash,role="execute"]

----

requirements (including yfinance), copies server.py, sets
`MCP_TRANSPORT=streamable-http`, exposes port 8080.

Check the deployment manifest:

[source,bash,role="execute"]
----
cat scaffold/deployment.yaml
----

Expected: A Deployment named `stock-market-mcp` with a container pointing to
the internal registry image, port 8080, tcpSocket readiness probe, resource
limits. A Service exposing port 8080.

== Exercise 4: Customize -- add a tool

Ask the agent to add a tenth tool:

----
Add a new tool to scaffold/server.py called "compare_stocks" that takes a
list of ticker symbols and returns a comparison table with each stock's
current price, market cap, P/E ratio, and 52-week range using yfinance.
----

Expected result: The agent edits `scaffold/server.py` and adds the new tool
with proper decorator, type hints, docstring, and error handling.

Verify:

[source,bash,role="execute"]
----
grep -c "@server.tool" scaffold/server.py
----

Expected result: `10` (nine original tools plus the new one).

== Exercise 5: Validate the artifacts

Run the workshop validation:

----

Expected result: All checks pass -- server.py exists, has MCPServer import,
has @server.tool decorators, has run() call, uses yfinance,
requirements.txt has mcp and yfinance, Containerfile and deployment.yaml exist.
