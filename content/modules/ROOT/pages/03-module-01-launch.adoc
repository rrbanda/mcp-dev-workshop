= Module 1: Launch Your Workspace
:navtitle: Launch Your Workspace

Your workspace is running and you have verified the LLM in the Prerequisites
page. Now get oriented -- learn where things are in the IDE, understand the
project layout, and confirm you are ready to build.

== Learning objectives

* Navigate the VS Code editor (file tree, terminal, ports).
* Locate the workshop project files and understand the directory structure.
* _(Agent mode)_ Send a message in the OpenCode chat and see the agent respond.
* _(Manual mode)_ Read a skill file and understand what it contains.

== Your IDE at a glance

You are working in *VS Code in the browser*, provided by Red Hat OpenShift
DevSpaces. Here is what you should see:

[cols="1,3",options="header"]
|===
| Area | What is there

| *Left sidebar -- file tree*
| The `/projects/mcp-dev-workshop` directory. Click any file to open it in
  the editor. You will spend most of your time in the `scaffold/` directory.

| *Bottom panel -- terminal*
| One or more terminal tabs. `oc`, `python`, `pip`, `curl`, `make` are all
  available. You are already logged in.

| *Top menu bar*
| File, Edit, Terminal, Help. Use *Terminal -> New Terminal* if you need
  another terminal tab.

| *Ports / Endpoints tab* _(if visible)_
| Shows exposed ports. Port 4096 is the OpenCode Web UI (agent mode only).
|===

== Exercise 1: Explore the project

In the file tree (left sidebar), expand `mcp-dev-workshop`. Or use the terminal:

[source,bash,role="execute"]
----
cd /projects/mcp-dev-workshop && find . -maxdepth 2 -type f | grep -v '.git/' | sort | head -25
----

Key directories and files:

[cols="1,3",options="header"]
|===
| Path | Purpose

| `scaffold/`
| Where you build your MCP server. Contains `server.py`, `requirements.txt`,
  `Containerfile`, `deployment.yaml`.

| `solutions/`
| Reference solutions for each module. Use these if you fall behind.

| `.opencode/skills/`
| Three Agent Skills (SKILL.md files) that teach MCP patterns, yfinance API,
  and the server specification. Used by the agent in agent mode; useful as
  reference docs in manual mode.

| `Makefile`
| Workshop commands: `make validate`, `make build-image`, `make deploy`,
  `make test-mcp`, `make clean`.

| `content/`
| The Antora source for this workshop guide. You can ignore this.
|===

== Exercise 2: Read a skill file

Skills are Markdown files that contain SDK patterns, API references, and
specifications. Even in manual mode, they are valuable documentation.

[tabs]
====
Agent Mode::
+
--
In the OpenCode chat, ask the agent to discover skills:

----
What skills do you have available? List them.
----

Expected result: The agent lists three skills -- `build-mcp-server`,
`yfinance-api`, and `stock-market-mcp-spec` -- with one-line descriptions.

Now ask it to load one:

----
Load the build-mcp-server skill and summarize what it teaches you.
----

Expected result: The agent reads the full SKILL.md and summarizes the MCP
Python SDK v2 patterns it learned.
--

Manual Mode::
+
--
Open the skill file in the editor (click it in the file tree) or read it in
the terminal:

[source,bash,role="execute"]
----
head -50 /projects/mcp-dev-workshop/.opencode/skills/build-mcp-server/SKILL.md
----

Skim the contents. Notice:

* It describes the `MCPServer` class, `@server.tool()` decorator pattern.
* It shows type hint to JSON Schema mapping.
* It covers transport modes (stdio vs streamable-http).
* It includes error handling and Containerfile patterns.

This is the same content the agent would load in agent mode. In manual mode,
you read it yourself as a reference guide.
--
====

== Exercise 3: Check the Makefile targets

The Makefile provides shortcuts you will use throughout the workshop:

[source,bash,role="execute"]
----
cd /projects/mcp-dev-workshop && make help 2>/dev/null || grep '^[a-z].*:' Makefile | head -15
----

Key targets you will use:

[cols="1,3",options="header"]
|===
| Target | What it does

| `make validate`
| Checks that `scaffold/server.py` exists, has the right imports and tools.

| `make build-image`
| Builds the container image on OpenShift via `oc new-build` + `oc start-build`.

| `make deploy`
| Applies `scaffold/deployment.yaml` to your namespace.

| `make test-mcp`
| Calls the deployed MCP server with a test request.

| `make clean`
| Deletes the deployment, service, build config, and image stream.
|===

== Exercise 4: Confirm your identity and namespace

[source,bash,role="execute"]
----
echo "User:      $(oc whoami)"
echo "Namespace: $(oc project -q)"
echo "API URL:   $OPENAI_BASE_URL"
echo "Model:     $VLLM_MODEL_ID"
----

Expected result: Four lines showing your username, namespace
(`<username>-devspaces`), the MaaS gateway URL, and the model ID.
All four must be non-empty.

[IMPORTANT]
====
If any value is empty or shows an error, *stop and ask the facilitator*.
The remaining modules depend on all four being set.
====
