= Module 5: Deploy to OpenShift
:navtitle: Deploy to OpenShift

Your MCP server works locally. Now you deploy it as a container on OpenShift so
any agent in the cluster can connect to it over the network — not just your
local OpenCode session.

== Learning objectives

* Build a container image using `oc new-build` from the DevSpaces terminal.
* Update the deployment manifest with your namespace.
* Deploy the MCP server with `oc apply`.
* Verify the pod is running and the service is reachable.

== Exercise 1: Build the container image

OpenShift's built-in image builder lets you build directly from your workspace
without needing Docker or Podman locally.

[source,bash,role="execute"]
----
cd /projects/mcp-dev-workshop/scaffold
----

Create the build configuration (first time only):

[source,bash,role="execute"]
----
oc new-build --binary --name=my-mcp-server --to=my-mcp-server:latest \
  --strategy=docker --dockerfile="$(cat Containerfile)" 2>/dev/null || \
  echo "BuildConfig already exists"
----

Start the build:

[source,bash,role="execute"]
----
oc start-build my-mcp-server --from-dir=. --follow
----

Expected result: The build runs on the cluster — pulls the UBI9 Python base
image, installs requirements, copies server.py. The build log ends with
`Push successful`. The image is now in the internal registry at:

----
image-registry.openshift-image-registry.svc:5000/<your-namespace>/my-mcp-server:latest
----

[CAUTION]
====
If the build fails with a pull error on the UBI9 image, ask the facilitator —
the cluster may need an image pull secret for `registry.access.redhat.com`.
====

== Exercise 2: Update the deployment manifest

The `deployment.yaml` has a placeholder `MY_NAMESPACE` that needs to be replaced
with your actual namespace:

[source,bash,role="execute"]
----
NAMESPACE=$(oc project -q)
sed -i "s/MY_NAMESPACE/${NAMESPACE}/g" /projects/mcp-dev-workshop/scaffold/deployment.yaml
----

Verify the image reference is correct:

[source,bash,role="execute"]
----
grep "image:" scaffold/deployment.yaml
----

Expected result: The image line shows your namespace:
`image-registry.openshift-image-registry.svc:5000/<your-namespace>/my-mcp-server:latest`

== Exercise 3: Deploy with oc apply

[source,bash,role="execute"]
----
oc apply -f /projects/mcp-dev-workshop/scaffold/deployment.yaml
----

Expected result:
----
deployment.apps/my-mcp-server created
service/my-mcp-server created
----

Wait for the pod to be ready:

[source,bash,role="execute"]
----
oc rollout status deployment/my-mcp-server --timeout=120s
----

Expected result: `deployment "my-mcp-server" successfully rolled out`

== Exercise 4: Verify the deployment

Check the pod is running:

[source,bash,role="execute"]
----
oc get pods -l app=my-mcp-server
----

Expected result: One pod in `Running` state with `1/1` ready.

Check the service:

[source,bash,role="execute"]
----
oc get svc my-mcp-server
----

Expected result: A ClusterIP service on port 8080.

Check the pod logs for startup:

[source,bash,role="execute"]
----
oc logs deployment/my-mcp-server --tail=10
----

Expected result: The server started in streamable-http mode on port 8080.

== Exercise 5: Test the deployed server

Use `curl` from inside the cluster to verify the server responds:

[source,bash,role="execute"]
----
oc exec deployment/my-mcp-server -- curl -s http://localhost:8080/health 2>/dev/null || \
  echo "Health endpoint may not be implemented — check logs above"
----

You can also use port-forwarding to test from your workspace:

[source,bash,role="execute"]
----
oc port-forward svc/my-mcp-server 9090:8080 &
sleep 2
curl -s http://localhost:9090/health 2>/dev/null; echo
kill %1 2>/dev/null
----

== Exercise 6: Run the verification

[source,bash,role="execute"]
----
cd /projects/mcp-dev-workshop
make verify
----

Expected result: All checks pass — deployment exists, is ready, service on
port 8080, pod logs show startup.

[TIP]
====
*Falling behind?* Copy the reference deployment and apply:

[source,bash,role="execute"]
----
NAMESPACE=$(oc project -q)
sed "s/MY_NAMESPACE/${NAMESPACE}/g" solutions/lab-05/deployment.yaml | oc apply -f -
----
