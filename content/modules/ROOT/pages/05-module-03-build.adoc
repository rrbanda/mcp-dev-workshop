= Module 3: Build an MCP Server
:navtitle: Build an MCP Server

This is the core module. You tell the AI agent what tools you want, the agent
loads the `build-mcp-server` skill, and generates a complete MCP server. You
review the code, understand the patterns, and optionally customize it.

== Learning objectives

* Use the agent and its loaded skill to generate an MCP server from a
  natural-language description.
* Identify the MCP Python SDK v2 patterns in the generated code: `MCPServer`,
  `@mcp.tool()`, type hints, docstrings, `mcp.run()`.
* Understand how type hints map to JSON Schema for tool parameters.
* Add or modify a tool in the generated server.

== Exercise 1: Ask the agent to build your MCP server

In the OpenCode chat, give the agent a clear description of what you want.
Here is a suggested prompt — feel free to customize it:

----
Build me an MCP server called "openshift-devops" with these tools:

1. list_pods - Lists pods in a given namespace with optional label filter
2. get_pod_logs - Gets recent log lines from a specific pod
3. get_route_url - Gets the public URL for an OpenShift Route
4. describe_resource - Describes any Kubernetes resource by kind, name, namespace

Put the server in scaffold/server.py. Also create scaffold/requirements.txt,
scaffold/Containerfile, and scaffold/deployment.yaml.

Use the oc CLI for cluster access (it's already authenticated in my terminal).
The server should support both stdio (for local dev) and streamable-http
(for deployment) transports based on an MCP_TRANSPORT environment variable.
----

Expected result: The agent loads the `build-mcp-server` skill and generates
four files:

* `scaffold/server.py` — the MCP server with all four tools
* `scaffold/requirements.txt` — with `mcp>=2.0`
* `scaffold/Containerfile` — UBI9 Python image, pip install, CMD
* `scaffold/deployment.yaml` — Deployment + Service for OpenShift

Watch the agent's output — you should see it reference the skill and
produce structured Python code.

[IMPORTANT]
====
If the agent produces code that uses `FastMCP` instead of `MCPServer`, ask it
to update the import. `FastMCP` was the v1 name — it is *removed* in SDK v2
(`from mcp.server.fastmcp import FastMCP` raises `ModuleNotFoundError`). The
correct v2 import is `from mcp.server import MCPServer`. What matters is that
the server defines tools with `@mcp.tool()`, has type hints, and calls
`mcp.run()`.
====

== Exercise 2: Review the generated code

Open `scaffold/server.py` in the IDE or terminal:

[source,bash,role="execute"]
----
cat scaffold/server.py
----

Check for these SDK v2 patterns:

[cols="1,2",options="header"]
|===
| Pattern | What to look for

| *Import*
| `from mcp.server import MCPServer` or similar

| *Server instance*
| `mcp = MCPServer("openshift-devops")`

| *Tool decorator*
| `@mcp.tool()` above each function

| *Type hints*
| `def list_pods(namespace: str, label: str = "") -> str:`

| *Docstring*
| Triple-quoted description with `Args:` section

| *Error handling*
| `try/except` around `subprocess.run()`

| *Timeout*
| `timeout=30` on subprocess calls

| *Transport switch*
| `MCP_TRANSPORT` env var → stdio or streamable-http

| *Entry point*
| `if __name__ == "__main__": mcp.run()`
|===

.Why do type hints matter?
[%collapsible]
====
MCP uses type hints to auto-generate JSON Schema for each tool's parameters.
When an agent connects to your server, it receives the schema and knows exactly
what arguments each tool expects — types, defaults, which are required.
This is how the agent knows to pass `namespace: "ai-serving"` as a string
and `tail: 50` as an integer.

`str` → `{"type": "string"}` +
`int` → `{"type": "integer"}` +
`bool` → `{"type": "boolean"}` +
`list[str]` → `{"type": "array", "items": {"type": "string"}}` +
Optional with default → `"required": false`
====

== Exercise 4: Customize — add a tool

Ask the agent to add a fifth tool to your server:

----
Add a new tool to scaffold/server.py called "get_events" that lists recent
events in a namespace using "oc get events -n <namespace> --sort-by=.lastTimestamp"
and returns the last 20 lines.
----

Expected result: The agent edits `scaffold/server.py` and adds the new tool
with proper decorator, type hints, docstring, error handling, and timeout.

Verify:

[source,bash,role="execute"]
----
grep -c "@mcp.tool" scaffold/server.py
----

Expected result: `5` (four original tools plus the new one).
