= Build and Deploy MCP Servers on Red Hat OpenShift AI
:navtitle: Introduction

From idea to deployed MCP server — using an AI agent to build its own tools.

This hands-on workshop teaches developers to create, test, and deploy
https://modelcontextprotocol.io/[Model Context Protocol (MCP)] servers using
OpenCode with Agent Skills inside Red Hat OpenShift DevSpaces. Everything runs
on a pre-configured OpenShift cluster with Red Hat OpenShift AI — participants
do no platform setup. You open a workspace, talk to an AI agent, and the agent
builds, tests, and helps you deploy an MCP server that extends its own
capabilities.

The AI agent uses a pre-loaded *Agent Skill* that teaches it MCP Python SDK v2
patterns. You tell the agent what tools you want; the skill guides the agent
to produce well-structured, deployable code. The result is a working MCP server
running on OpenShift that any agent in the cluster can connect to.

== Learning objectives

By the end of the workshop you will be able to:

* Explain how Agent Skills extend an AI coding agent's knowledge.
* Use OpenCode and a pre-loaded skill to generate an MCP server with proper
  tool definitions, type hints, and transport configuration.
* Test an MCP server locally using stdio transport and the MCP Inspector.
* Build a container image and deploy the server to OpenShift with `oc apply`.
* Wire an AI agent to a deployed remote MCP server and call tools through it.
* Describe how MCP fits into the Red Hat OpenShift AI inference stack
  (MaaS, llm-d, EPP, DevSpaces).

== How to run the workshop

Each exercise identifies the action to take, the evidence to inspect, and the
result that must be verified. *Do not treat command completion as proof.* Compare
the observed output with the stated pass condition before continuing.

Facilitators provisioning environments ahead of class: see

== Choose your track by allotted time

The navigation groups the modules into two tracks. Pick by the time you have:

* *Core track — about 90 minutes*: Modules 1 through 6. Launch your workspace,
  understand skills, build an MCP server with the agent, test it locally, deploy
  to OpenShift, and close the feedback loop by wiring the agent to its own
  deployed server.
* *Extended track — about 2.5 hours total*: adds Modules 7 and 8 to the core —
  multi-server composition and enterprise governance patterns.

Dependencies:

* Modules are sequential in the core track. Each module depends on the previous one.
* Module 7 (composition) requires Module 6 (deployed and wired server).
* Module 8 (governance) is a guided discussion; it requires only a running cluster.

== Technical model

MCP separates *what an agent can do* (tools exposed by servers) from *how the
agent reasons* (the LLM behind the agent). The MCP server is a standalone
process — a container on OpenShift — that exposes tools over a standard
protocol. The agent discovers tools at connection time and calls them by name
with typed arguments.

In this workshop the stack is:

* *OpenCode* — the AI coding agent running inside DevSpaces.
* *Agent Skill* — a SKILL.md file that teaches OpenCode MCP SDK patterns.
* *MCP Server* — the Python server you build, containing tool definitions.
* *llm-d + vLLM* — the LLM inference backend providing the model.
* *MaaS (Model as a Service)* — the API gateway with authentication and rate limiting.
* *OpenShift DevSpaces* — the cloud IDE environment where everything runs.

The developer loop: *ask the agent → agent loads skill → agent writes code →
developer tests → developer deploys → agent uses what it built*.
