= Build and Deploy MCP Servers on Red Hat OpenShift AI
:navtitle: Introduction

From idea to deployed MCP server -- on Red Hat OpenShift AI.

This hands-on workshop teaches developers to create, test, and deploy
https://modelcontextprotocol.io/[Model Context Protocol (MCP)] servers
inside a cloud workspace on OpenShift. Everything runs on a pre-configured
cluster with Red Hat OpenShift AI -- participants do no platform setup.
You log in, open your workspace, and start building.

== Your environment

Each participant gets a personal cloud workspace powered by
*Red Hat OpenShift DevSpaces*. Inside that workspace you have:

* A *VS Code editor in the browser* -- file tree, syntax highlighting,
  integrated terminal. This is your IDE for the entire workshop.
* A *terminal* with `oc`, `python`, `pip`, `curl`, and `make` pre-installed
  and pre-authenticated.
* _(Agent mode)_ An *OpenCode Web UI* -- an AI chat interface that runs
  alongside VS Code in the same workspace.

All you need is a web browser and the credentials card your facilitator
provides. No local tooling required.

== Choose your mode

The workshop offers *two modes* -- choose the one that fits your style:

[tabs]
====
AI-Assisted (Agent Mode)::
+
You use the OpenCode AI chat interface alongside the VS Code editor.
OpenCode has pre-loaded *Agent Skills* that teach it MCP Python SDK v2
patterns, the yfinance library API, and the exact specification for a stock
market data server. You describe what tools you want; the agent generates
well-structured, deployable code. You review, customize, and deploy.
+
_Best for: developers who want to experience AI-assisted development and
learn how Agent Skills work._

Manual (CLI Mode)::
+
You use the VS Code editor and terminal for everything. You read the
reference MCP server code, understand the SDK v2 patterns yourself, edit the
scaffold files, and run `oc` and `curl` commands to build, deploy, and test.
The same Makefile, the same Containerfile, the same deployment.yaml -- you
drive everything from the editor and terminal.
+
_Best for: developers who prefer to understand every line before running it,
or environments where the LLM is not available._
====

Both modes produce the same outcome: a working stock market MCP server
deployed on OpenShift with 9 tools, reachable over streamable-http.
You can switch modes at any time -- every module page has tabs showing
instructions for both.

== Learning objectives

By the end of the workshop you will be able to:

* Explain how MCP separates tool definitions from agent reasoning.
* Build an MCP server using the Python SDK v2 with proper tool definitions,
  type hints, and transport configuration.
* _(Agent mode)_ Explain how Agent Skills extend an AI coding agent's knowledge.
* Test an MCP server locally using stdio transport.
* Build a container image and deploy the server to OpenShift with `oc apply`.
* Wire a client (AI agent or `curl`) to a deployed remote MCP server and
  call tools.
* Describe how MCP fits into the Red Hat OpenShift AI inference stack
  (MaaS, llm-d, EPP, DevSpaces).

Where you see tabs at the top of an exercise, click your mode (Agent or Manual)

== Choose your track by allotted time

* *Core track -- about 90 minutes*: Modules 1 through 6. Launch your workspace,
  understand MCP patterns, build an MCP server, test it, deploy to OpenShift,
  and close the feedback loop.
* *Extended track -- about 2.5 hours total*: adds Modules 7 and 8 --
  multi-server composition and enterprise governance patterns.

Dependencies:

* Modules are sequential in the core track. Each one depends on the previous.
* Module 7 (composition) requires Module 6 (deployed and wired server).
* Module 8 (governance) is a guided discussion; it requires only a running cluster.

== Technical model

MCP separates *what a client can do* (tools exposed by servers) from *how the
agent reasons* (the LLM). The MCP server is a standalone process -- a container
on OpenShift -- that exposes tools over a standard JSON-RPC protocol. Any client
(an AI agent or a `curl` command) can discover tools at connection time and call
them by name with typed arguments.

In this workshop the stack is:

* *VS Code (che-code)* -- browser-based editor provided by DevSpaces. Both tracks.
* *OpenCode* _(agent mode)_ -- AI coding agent running inside the workspace.
* *Agent Skills* -- SKILL.md files that teach OpenCode MCP SDK patterns.
* *MCP Server* -- the stock market Python server you build (9 tools).
* *llm-d + vLLM* -- the LLM inference backend providing the model.
* *MaaS (Model as a Service)* -- the API gateway with authentication.
* *OpenShift DevSpaces* -- the cloud workspace platform.
