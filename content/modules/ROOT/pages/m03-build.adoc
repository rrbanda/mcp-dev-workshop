= Build from Reference
:navtitle: Build from Reference

This is the core module. You copy the reference MCP server implementation,
read through the code to understand the patterns, and optionally customize it.

== Learning objectives

* Produce a working MCP server with 9 stock market tools.
* Identify the MCP Python SDK v2 patterns in the code: `MCPServer`,
  `@server.tool()`, type hints, docstrings, `server.run()`.
* Understand how type hints and Enum classes map to JSON Schema for tool
  parameters.
* Add a tool manually following the established patterns.

== Exercise 2: Review the code

Open `scaffold/server.py` in the IDE or terminal:

[source,bash,role="execute"]
----
cat scaffold/server.py
----

Check for these SDK v2 patterns:

[cols="1,2",options="header"]
|===
| Pattern | What to look for

| *Import*
| `from mcp.server import MCPServer` and `import yfinance as yf`

| *Server instance*
| `server = MCPServer("stock-market", instructions="...")`

| *Enum types*
| `FinancialType`, `HolderType`, `RecommendationType` as `str, Enum` subclasses

| *Ticker normalization*
| `normalize_ticker()` function converting `BRK.B` to `BRK-B`

| *Tool decorator*
| `@server.tool(name="...", description="...")` above each function

| *Async tools*
| `async def get_stock_info(ticker: str) -> str:`

| *Type hints*
| Enum types in parameters, `float` or `None`, `list[str]` or `None`

| *Error handling*
| `try/except Exception` wrapping all tool bodies

| *Transport switch*
| `MCP_TRANSPORT` env var selects stdio or streamable-http

| *Entry point*
| `if __name__ == "__main__": main()`
|===

.Why do type hints and Enums matter?
[%collapsible]
====
MCP uses type hints to auto-generate JSON Schema for each tool's parameters.
When a client connects to your server, it receives the schema and knows exactly
what arguments each tool expects -- types, defaults, which are required.

`str` maps to `{"type": "string"}` +
`int` maps to `{"type": "integer"}` +
`float | None` maps to `{"type": "number"}` (nullable) +
`FinancialType` enum maps to `{"enum": ["income_stmt", "quarterly_income_stmt", ...]}` +
Optional with default means `"required": false`

Enums are especially powerful -- a client sees the exact valid values and never
passes an invalid financial type.
====

== Exercise 4: Customize -- add a tool

Open `scaffold/server.py` in the editor and add a tenth tool manually.
Follow the same pattern as the existing tools:

[source,python]
----
@server.tool(name="compare_stocks", description="Compare key metrics for multiple stocks")
async def compare_stocks(tickers: list[str]) -> str:
    """Compare current price, market cap, P/E ratio, and 52-week range."""
    try:
        results = []
        for t in tickers:
            ticker = yf.Ticker(normalize_ticker(t))
            info = ticker.info
            results.append({
                "ticker": t,
                "price": info.get("regularMarketPrice"),
                "market_cap": info.get("marketCap"),
                "pe_ratio": info.get("trailingPE"),
                "52w_high": info.get("fiftyTwoWeekHigh"),
                "52w_low": info.get("fiftyTwoWeekLow"),
            })
        return json.dumps(results, indent=2)
    except Exception as e:
        return json.dumps({"error": str(e)})
----

Verify:

[source,bash,role="execute"]
----
grep -c "@server.tool" scaffold/server.py
----

Expected result: `10` (nine original tools plus the new one).
