= Module 7: Multi-Server Composition
:navtitle: Multi-Server Composition

Real-world agents connect to *multiple* MCP servers -- each providing tools for
a different domain. In this module you create a second MCP server and wire both
into a client, then observe cross-server tool calls.

== Learning objectives

* Create a second MCP server with a different tool set.
* Configure a client to connect to multiple MCP servers simultaneously.
* Observe tool routing to the correct server.
* Understand the composition model: one client, many tool providers.

== Exercise 3: Connect both servers

[tabs]
====

Configure OpenCode with both MCP servers:

I have two MCP servers now:

1. stock-market (deployed) at
   http://stock-market-mcp.<namespace>.svc:8080/mcp
   via streamable-http

2. project-helper (local) at
   scaffold/project-helper.py via stdio

----

Ask a cross-server question:

----
Find all Python files in my project that import "yfinance" and also get the
current stock price for AAPL.
----

Expected result: The agent calls `search_code` from project-helper AND
`get_stock_info` from stock-market, combining results.
--

Manual Mode::
+
--
Run both servers and call tools via `curl`. The deployed stock-market server
is already running. Start the project-helper locally:

[source,bash,role="execute"]
----
cd /projects/mcp-dev-workshop/scaffold
MCP_TRANSPORT=streamable-http python project-helper.py &
PH_PID=$!
sleep 2
----

Call a tool on each server:

[source,bash,role="execute"]
----
NAMESPACE=$(oc project -q)

# Initialize stock-market (deployed)
SM_URL="http://stock-market-mcp.${NAMESPACE}.svc:8080/mcp"
SM_RESP=$(curl -sD /tmp/sm-headers -X POST "$SM_URL" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"test","version":"1.0"}}}')
SM_SID=$(grep -i mcp-session-id /tmp/sm-headers | tr -d '\r' | awk '{print $2}')

echo "Stock-market tools:"
curl -s -X POST "$SM_URL" \
  -H "Content-Type: application/json" \
  -H "Mcp-Session-Id: $SM_SID" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}' | python3 -m json.tool | grep '"name"'
----

[source,bash,role="execute"]
----
# Initialize project-helper (local)
PH_URL="http://localhost:8080/mcp"
PH_RESP=$(curl -sD /tmp/ph-headers -X POST "$PH_URL" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"test","version":"1.0"}}}')
PH_SID=$(grep -i mcp-session-id /tmp/ph-headers | tr -d '\r' | awk '{print $2}')

echo "Project-helper tools:"
curl -s -X POST "$PH_URL" \
  -H "Content-Type: application/json" \
  -H "Mcp-Session-Id: $PH_SID" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}' | python3 -m json.tool | grep '"name"'
----

Call one tool from each:

[source,bash,role="execute"]
----
echo "=== Stock info (from stock-market server) ==="
curl -s -X POST "$SM_URL" \
  -H "Content-Type: application/json" \
  -H "Mcp-Session-Id: $SM_SID" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_stock_info","arguments":{"ticker":"AAPL"}}}' | python3 -m json.tool | head -15

echo ""
echo "=== Git status (from project-helper server) ==="
curl -s -X POST "$PH_URL" \
  -H "Content-Type: application/json" \
  -H "Mcp-Session-Id: $PH_SID" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_git_status","arguments":{}}}' | python3 -m json.tool | head -15
----

Clean up the local server:

[source,bash,role="execute"]
----
kill $PH_PID 2>/dev/null
----

== Exercise 4: Understand the composition model

[mermaid]
....
flowchart TD
    Client["Client (agent or curl)"]
    S1["stock-market<br/>prices, news, options, financials"]
    S2["project-helper<br/>search_code, list_files, git_status"]
    S3["future server<br/>database, monitoring, ..."]

    Client <-->|streamable-http| S1
    Client <-->|stdio or http| S2
    Client <-.->|any transport| S3
....

Key properties of MCP composition:

[cols="1,2",options="header"]
|===
| Property | Detail

| *Independent servers*
| Each server is a separate process or container. They do not know about each other.

| *Client-side routing*
| The client (or agent LLM) decides which server's tool to call based on the
  tool name and description.

| *Mixed transports*
| Some servers can be local (stdio), others deployed (streamable-http).

| *Dynamic discovery*
| When a client connects to a server, it discovers all tools automatically.
  No hardcoded tool list.

| *Additive*
| Adding a new server adds capabilities. Existing servers are unaffected.
|===
