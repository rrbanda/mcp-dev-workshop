= Module 6: Close the Feedback Loop
:navtitle: Close the Feedback Loop

The defining moment of this workshop: the AI agent uses the MCP server *it
helped build*. You wire OpenCode to the deployed remote server, and the agent
calls tools that are running as a container on OpenShift — not as a local
process.

== Learning objectives

* Configure OpenCode to connect to a deployed MCP server via streamable-http.
* Observe the agent calling tools over the network (not stdio).
* Reflect on the full developer loop: ask → build → test → deploy → use.

== Exercise 1: Get the service URL

Your MCP server is running as a ClusterIP Service. From inside the cluster
(which is where your DevSpaces workspace runs), you can reach it directly:

[source,bash,role="execute"]
----
NAMESPACE=$(oc project -q)
echo "http://my-mcp-server.${NAMESPACE}.svc.cluster.local:8080"
----

Expected result: A URL like
`http://my-mcp-server.dev-user1-devspaces.svc.cluster.local:8080`

== Exercise 2: Wire OpenCode to the remote server

In the OpenCode chat, tell the agent about the deployed server:

----
I have an MCP server deployed on OpenShift. Connect to it using streamable-http transport at:
http://my-mcp-server.<your-namespace>.svc.cluster.local:8080/mcp

Replace <your-namespace> with my actual namespace.
----

Or if OpenCode supports MCP configuration directly, the config would look like:

[source,json]
----
{
  "mcpServers": {
    "openshift-devops-remote": {
      "url": "http://my-mcp-server.<namespace>.svc.cluster.local:8080/mcp",
      "transport": "streamable-http"
    }
  }
}
----

Expected result: OpenCode connects to the remote MCP server and discovers the
same tools as before — but now they are running in a separate container, not as
a local process.

== Exercise 3: Agent uses what it built

Ask the agent to use the deployed tools:

----
Using the remote MCP server, describe the my-mcp-server deployment in my namespace.
----

Expected result: The agent calls the `describe_resource` tool on the remote
MCP server, which runs `oc describe deployment my-mcp-server` inside its own
container and returns the output. The agent is now querying its own deployment.

Try more:

----
List all pods in my namespace and show me the logs from the MCP server pod.
----

The agent chains `list_pods` → identifies the MCP server pod → calls
`get_pod_logs` on it. The MCP server is reporting its own logs back through
the agent.

== Exercise 4: Reflect on the loop

Take a moment to trace what happened:

. *You asked the agent* to build an MCP server.
. *The agent loaded a skill* that taught it MCP SDK patterns.
. *The agent generated code* — server.py, Containerfile, deployment.yaml.
. *You tested locally* — the server worked via stdio.
. *You deployed to OpenShift* — the server runs as a container.
. *You wired the agent to the deployed server* — streamable-http transport.
. *The agent uses the tools it built* — querying the cluster through its own server.

This is the *agent tool development loop*: the AI helps build tools, the tools
extend the AI's capabilities, and the extended AI can help build better tools.
